# Onboarding Success Criteria (v0.1)
Version: 0.1  
Status: Active  
Last Updated: 2025-12-31

---

## Purpose

Onboarding exists to establish a **safe, stable, and unambiguous starting point** for AI-based coaching.  
Its goal is *orientation*, not transformation.

Onboarding **does not**:
- Solve the user’s problems
- Provide therapy or diagnosis
- Commit to outcomes or timelines
- Replace human support

---

## Definition of “Onboarding Complete”

Onboarding is complete **only when all required conditions below are satisfied**.  
Partial completion is not allowed.

---

## 1. Identity Clarity (Required)

The system must capture:

- Preferred name
- Timezone
- Primary language
- Self-described current life state (free text)
- Self-reported emotional baseline  
  (`low` / `medium` / `high` distress)

### Success
- The system can generate a **one-paragraph neutral identity summary**
- No guessing, no inference beyond what the user shared

### Failure
- User refuses all self-description
- Irreconcilable contradictions
- Emotional distress too high to proceed safely

---

## 2. Intent Articulation (Required)

The user must express **at least one meaningful intent** in their own words.

Examples:
- “I want structure in my life”
- “I’m sabotaging my health”
- “I’m stuck and don’t know why”

The system must store:
- Raw user intent (verbatim)
- Normalized intent label (generated by IOA)

### Success
- Intent maps to **at least one coaching domain**

### Failure
- Persistent “I don’t know” without elaboration
- Expectation that the system decides goals for the user

---

## 3. Coach Routing Decision (Required)

The Identity & Onboarding Agent (IOA) must determine:

- **Primary coach type**
- Up to **two secondary flags** (optional)

The decision must be **explainable in one sentence**.

Example:
> “Foundational coach first due to low motivation and diffuse goals.”

### Success
- A single coach can begin without missing context

### Failure
- Multiple conflicting coaches required immediately
- No safe starting coach exists

---

## 4. Initial Commitment Surface (Required)

The user must choose **one interaction mode**:

- Daily check-ins
- Scheduled calls
- Passive tracking only

No promises or behavioral commitments required.

### Success
- Cadence is explicitly chosen

### Failure
- User refuses any ongoing interaction
- User expects automatic fixing without participation

---

## 5. Safety & Boundary Acknowledgement (Required)

The user must accept that:

- This is not medical or psychological treatment
- The system supports reflection and structure, not emergency care

### Success
- No expectation mismatch remains

### Failure
- Requests for diagnosis, guarantees, or crisis intervention

---

## System Outputs on Success

When onboarding completes, the system persists:

- `identity_profile`
- `onboarding_summary` (immutable snapshot)
- `coach_handoff_payload`
- `onboarding_status = complete`

---

## System Outputs on Failure

If onboarding cannot complete:

- `onboarding_status = blocked`
- `block_reason` (enum)
- Suggested next action  
  (`retry` / `pause` / `human_support`)

---

## Final Gate Rule

> **If the system cannot clearly explain who the user is, what they want, and why a specific coach is appropriate — onboarding is NOT complete.**
